# Content ownership

This checkout uses the existing Laravel 10 CMS/PostgreSQL backend and Next.js App Router.
There is no Payload installation or second backend.

| Content | Owner |
| --- | --- |
| Home, About, Portfolio, digital marketing, non-Amazon SEO, animation, Privacy, Terms | Explicit frontend routes and frontend/src/data/pages |
| Amazon, Development and contact pages, including SEO | CMS pages/services and typed sections |
| Blog listing, articles and SEO | CMS blogs, categories, settings and queries |
| Header, mega menu, footer, contact information, floating form | CMS menus, settings and global sections |
| Forms and blog cards embedded in static pages | CMS global sections; placement belongs to the static page |

The static routes use renderStaticPage and staticPageService. CMS routes use pageDataService,
servicePageService and blogService. Both retain the existing section renderer and service layouts.
Dynamic readers never load a local document. Missing/unpublished CMS pages produce not-found;
API failures propagate. A static frontend page is never a substitute for a missing CMS page.

Static page metadata is frontend-owned. Dynamic titles, descriptions, canonical, robots,
Open Graph and Twitter values come from seo_metas; JSON-LD is generated by the backend.
Metadata is rendered on the server alongside the page.
Authored page titles are rendered verbatim; the layout title template cannot append a second brand suffix.

## CMS and APIs

Editors use the existing typed section fields/repeaters, persisted in ContentBlockField.
Global documents have no public URL or SEO. For example, home-sections contains the Home form's
labels and blog cards. cmsFields in a static document declares which fields to fetch and contains
no duplicate values. Missing required CMS sections are reported rather than filled with local defaults.

Read responses use { "success": true, "data": ... }:

- /api/frontend/site: menus, footer, contact, countries, site metadata and floating form.
- /api/frontend/pages, /pages/slugs, /pages/{slug}: CMS page documents.
- /api/frontend/root-pages/slugs, /root-pages/{slug}: root URLs and service aliases.
- /api/frontend/service-pages, /service-pages/slugs, /service-pages/{slug}: Development pages.
- /api/frontend/globals/{slug}: reusable sections without page metadata.
- /api/frontend/blog-index?page=N, /blogs, /blogs/recent, /blogs/{slug}: blog content.
- POST /api/forms: all six forms, validation, spam protection and inquiry persistence.

The frontend proxy forwards backend validation errors and reports only confirmed success.
Reference files travel as multipart uploads, are validated for type and a 5 MB limit, and are
stored privately. Downloads require an authenticated admin. Inquiry deletion removes the file.

## Caching

FRONTEND_API_CACHE_STORE=redis caches expensive read responses using versioned keys,
application/environment prefixes and bounded TTLs. Blog reads default to 300 seconds.
Committed content edits and SEO-only changes invalidate cached responses and notify the frontend
/api/revalidate webhook. Older versioned keys expire naturally.

Next.js uses tagged time-based revalidation plus the webhook; React memoizes reads within a render.
Forms use no-store. Redis failures can bypass the cache and read the same database; they never
change the content source. Query exceptions propagate once. TTL overrides live in configuration
so Laravel config:cache preserves them.

Set matching FRONTEND_REVALIDATE_SECRET and CMS_REVALIDATION_SECRET, with
FRONTEND_REVALIDATE_URL pointing to the frontend webhook. Tests use an isolated array cache
and disable real webhook calls.

## Migration and initialization

The ownership migration retains former static-page CMS records as inactive historical sources
outside APIs/admin editing, and copies only their forms/feeds into global documents. Current static
copy and SEO were exported before changing ownership. Static URLs are reserved in CMS validation,
APIs and the sitemap. Historical records are retained for recovery, not used as runtime content.

WebsiteContentSeeder initializes 12 routable CMS pages, six global documents, nine Development
services and 16 blogs. Backend fixtures are only for initialization: APIs never read them.
Reruns preserve editor changes, drafts and removed sections. Frontend static pages are not seeded.
Transfer later editorial changes using database/media backups.

Verify with backend php artisan test, frontend npm test and npm run build with the API available.
Generate sitemaps with php artisan sitemap:generate --force.
